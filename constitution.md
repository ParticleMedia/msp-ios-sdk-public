# MSP iOS SDK Development Constitution (Federal)
> **Version**: 1.0
> **Last Updated**: 2026-01-12
> **Scope**: Global (Applies to the entire project)
> **Status**: Active

This document defines the universal, immutable core principles for the project. All subdirectory constitutions augment, but cannot override, these articles.

---
## Article I: The Principle of Automation & Determinism
**Core Tenet**: Trust scripts, not manual actions. Every build must be reproducible.

**1.1 (Automation First)**: Any manual operation repeated more than twice must be scripted.
**1.2 (Deterministic Builds)**: [Non-Negotiable] Directly modifying `.xcodeproj` or `.xcworkspace` files is strictly forbidden. All project structure changes must be done by modifying `*.yml.template` files and then running XcodeGen.
**1.3 (Single Source of Truth - SSOT)**: The root `Podfile` is the single, authoritative source for all third-party dependency versions.
**1.4 (Sanctity of the Automated Process)**: [Highest Priority] When resolving any issue related to "build," "dependency," or "environment," temporary manual workarounds are **strictly forbidden**. The solution must always be to fix the underlying script or configuration.

> **Example Scenario**: A script fails because a framework is missing.
>
> ❌ **Incorrect (Unconstitutional) Action**: Manually creating the missing framework to make the script pass.
>
> ✅ **Correct (Constitutional) Action**:
> 1.  **Analyze**: Identify why the build script failed to generate the framework.
> 2.  **Fix**: Modify the **build script itself** to resolve the issue at its root.
> 3.  **Verify**: Re-run the **complete, high-level** automation script to validate the fix.

---
## Article II: The Validation-Driven Imperative
**Core Tenet**: The value of all changes is proven by automated validation.

**2.1 (The Validation Loop)**: Any meaningful change must successfully pass all relevant automated validation gates.
**2.2 (Local Verification First)**: Before committing, it is mandatory to run `./Scripts/target-switching/round-trip-test.sh` to ensure compatibility.

---
## Article III: The Principle of Modularity
**Core Tenet**: Every module and every class should do one thing well. Interactions should be defined by protocols, not concrete implementations.

**3.1 (Module Cohesion)**: `Core` modules handle generic logic; `Adapters` interface with third-party SDKs. It is strictly forbidden to import any third-party ad SDK headers directly within a `Core` module.
**3.2 (Protocol-Oriented Design)**: Adhere to established design patterns like the `AdNetworkAdapter` protocol.
